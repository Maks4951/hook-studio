# Hook Studio — генератор варіацій модифікацій для SockLock

MVP для домашнього завдання MarTech. Дизайнер завантажує відео-переможця і один раз розмічає, де в ньому
звучить чи з'являється кожен текст і де він стоїть у кадрі. Утиліта генерує 10–30 варіантів тексту саме під
цю розмітку (ліміт слів рахується з тривалості кожного сегмента), показує їх поверх відео, дає схвалити
й поправити і вивантажує бриф з таймкодами й позиціями. Окремо міряє час на текстову частину модифікації для пілоту.

**Проблема:** для $800k spend потрібно ~500 модифікацій на місяць, команда робить ~240, і близько половини
з 3 годин на модифікацію йде на ручне переписування текстів. Мета утиліти — 3 → 2 год на модифікацію.

## Як це працює

```
Бібліотека ──► Розмітка відео ──► Генерація ──► Перегляд ──► Бриф
(скрипт,       (сегменти на       (3 режими,     (прев'ю,      (CSV/JSON з таймкодами
 метрики,       таймлайні, позиції  ліміти слів     беру/не беру,  і позиціями
 відео)         й стиль тексту)     з розмітки)     правки,        + журнал пілоту)
                                                    таймер)
```

**Розмітка.** Сегменти (хук, перша фраза, текст на екрані, CTA, свій текст) тягнуться мишкою по шкалі часу:
край — початок/кінець, блок — зсув. Є кнопки «Початок тут / Кінець тут» за поточним кадром і поля з точністю 0,1 с.
Текст у кадрі перетягується мишкою; вигляд (плашка / субтитр / бейдж), розмір і вирівнювання — для кожного сегмента.
Червоні зони показують, де інтерфейс Reels приблизно перекриває кадр. Без ручної розмітки діє автоматична
(20% / 53% / 100% тривалості ролика; для 15 с це 0–3 / 3–8 / 8–15 с).

**Ліміт слів = тривалість × швидкість:** мова ~2,5 слова/с, текст на екрані ~2 слова/с (не більше 7 слів).

| Режим генерації | Що потрібно | Якість |
|---|---|---|
| **Шаблони формул** | нічого | базова: 15 прийомів × 2 зв'язні трійки, до 30 варіантів; ті, що вміщаються в ліміти, — першими; CTA і свої сегменти не змінюють |
| **Промпт для Claude** | будь-який чат з Claude | висока: утиліта збирає промпт і перевіряє JSON-відповідь |
| **API** | `ANTHROPIC_API_KEY` на сервері | висока, одним кліком |

Режими Claude і API використовують **той самий промпт** (`src/lib/prompt.js`) і **той самий розбір відповіді**.

## Запуск

Потрібен Node.js 18+.

```bash
npm install
npm run dev        # http://localhost:5173 — шаблони і режим Claude
npm test           # 30 тестів: генератори, розмітка, API-функція
npm run build      # збірка в dist/
```

API-режим локально (потрібен [Vercel CLI](https://vercel.com/docs/cli)):

```bash
cp .env.example .env   # вписати ANTHROPIC_API_KEY
npx vercel dev         # фронтенд + функція /api/generate
```

### Деплой на Vercel

1. Import Project → цей репозиторій. Vercel сам розпізнає Vite.
2. (Необов'язково) Settings → Environment Variables → `ANTHROPIC_API_KEY`. Без ключа API-режим вимкнений, решта працює.

## Структура

```
api/generate.js            Node.js-функція Vercel: виклик Claude API (ключ лише на сервері)
src/lib/schema.js          модель даних: Winner, Variant
src/lib/timeline.js        розмітка відео: сегменти, ліміти слів, позиції, автоматична розмітка
src/lib/templates.js       режим «Шаблони»
src/lib/prompt.js          промпт + розбір відповіді моделі
src/lib/variants.js        нормалізація, перевірка довжини, дублікати — спільні для всіх режимів
src/lib/export.js          CSV/JSON експорт
src/hooks/useActiveTimer.js активний таймер (пауза, якщо вкладка прихована або 5 хв без дій)
src/hooks/useClock.js      спільний годинник відео і таймлайну
src/components/            5 екранів: Library, Markup (+TimelineEditor), Generate, Review, Brief; VideoStage — кадр з текстом
tests/                     node:test, без сторонніх бібліотек
```

**Обмеження MVP (свідомі):** відео не завантажується на сервер, а відкривається в браузері (на Vercel немає
постійного диска); дані зберігаються в localStorage браузера і вивантажуються через CSV/JSON;
текст накладається HTML-шаром у прев'ю, рендеру MP4 немає; розмітка ручна. Тестові переможці вигадані.

## Як міряємо успіх

Пілот: 2 дизайнери × 2 тижні, половина модифікацій з утилітою, половина як зараз.
Дані для метрик утиліта збирає сама: журнал пілоту на екрані «Бриф» → «Експорт журналу CSV».

| Метрика | Зараз | Ціль пілоту (2 тижні) | Звідки дані |
|---|---|---|---|
| Час на модифікацію | ~3 год | ≤ 2,25 год (−25%), ціль повної версії — 2 год | журнал пілоту + тайм-трекінг монтажу |
| Активний час на тексти | ~1,5 год | ≤ 30 хв | таймер утиліти |
| Частка схвалених варіантів | — | ≥ 30% | журнал пілоту |
| Модифікацій на дизайнера на тиждень | ~10 | +25% | Airtable / облік команди |
| Win rate і CPA модифікацій (захисні) | поточні | не гірші за ручні модифікації | Meta Ads, через 2–4 тижні після запуску |

Рішення про повну версію — після пілоту: якщо час на модифікацію впав щонайменше на 25%,
а win rate і CPA не погіршилися.

## Наступна ітерація

1. **Автоматична розмітка:** розпізнавання мови (Whisper) дає текст із таймкодами, ffmpeg знаходить склейки — дизайнер лише перевіряє.
2. **Спільна бібліотека:** відео у Vercel Blob, переможці й сесії в базі або Airtable SockLock замість localStorage.
3. **Автонакладання тексту на відео:** позиції вже зберігаються у % кадру, тож розмітка напряму передається в Shotstack API або ffmpeg — частина модифікацій без дизайнера.
4. **Навчання на результатах:** підтягувати метрики модифікацій з Meta і давати моделі приклади хуків, що перемогли.
5. **Бренд-гайд і заборонені формулювання** в промпті + автоматична перевірка на правила Meta.
6. **Локалізація** тих самих варіантів для UK/CA/AU і тестів DE/FR.
